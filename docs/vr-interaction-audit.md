# VR: текущий аудит покрытия взаимодействий

Ревизия **18 октября 2026**. Сводка заменяет прежнюю накопительную таблицу: прежние диагнозы и этапы сохранены в Git history и `checkpoint.md`. Не следует читать старую запись «адаптера нет» как статус текущего кода.

База ревизии: тест `c8fbe61` и последующая пачка death/haptic + radio/turn/TV/easel fixes. Пользователь сообщил регрессию TV и краш при открытии мольберта; процесс теста завершился. Новые исправления до следующего запуска имеют только статическую проверку. Цель — чистый публичный Windows x64 IL2CPP host **v2026.10.15**, Unity **6000.3.12f1**, BepInEx **6.0.0-be.788**, Il2CppInterop **1.5.3**, OpenXR **1.16.1**, Oculus Touch / Quest 3S. Unity checkout использован только для чтения исходников. Совпадение сборки с interop не доказывает идентичность всех исходников бинарнику.

Код новой пачки проверяется **статически**. По разрешению пользователя запущен чистый публичный host с `c8fbe61`; затем процесс не перезапускался, сцены/команды агентом не переключались. Unity не запускалась. Функции, добавленные после последней пользовательской проверки, не получили автоматически статус «работает». Числовой процент готовности не приводится: прохождение всей игры контроллерами не подтверждено.

## Значение статусов

- **Подтверждено пользователем** — конкретное действие/изображение в шлеме ранее подтверждено; это не полная регрессия последнего коммита.
- **Реализовано, нужна приёмка** — адаптер есть и прошёл сборку/static interop audit; нативный перехват и поведение в шлеме могут оставаться непроверенными.
- **Частично / пробел** — есть существующий маршрут, но часть действий или отдельный desktop-only путь ещё не покрыты.
- **Не определено** — наблюдение есть, причина и исправление не установлены.

## Управление и ограничения приседания

Правый стик нужно вернуть в центр и отклонить вниз; следующий такой жест переключает обратно. Neutral threshold 0.25, downward threshold 0.7, боковая составляющая при срабатывании не более 0.35. Сильное отклонение вверх/вбок разоружает жест до центра, чтобы поворот/диагональ не превращались в приседание. UI scroll и selfie продолжают использовать вертикальную ось. Правый click остаётся морганием/help, левый click — режимом спринта из настроек.

Физическое приседание имеет отдельный hysteresis: вход ниже -0.35 м от калибровки, выход выше -0.2 м. Sit получается как physical OR toggle, поэтому выключение toggle не заставляет встать физически присевшего игрока. Выбранное toggle-состояние сохраняется при временной блокировке UI, но новый жест там не принимается; штатный input state по-прежнему определяет передачу Sit игроку. Переход сцены, смена player, смерть, потеря головы или правого контроллера сбрасывают toggle, затем требуется neutral. Комфорт камеры при этих границах требует шлема; программная проверка не заменяет его.

## Предлагаемые направления следующей пачки

1. **Удобство интерфейса:** U1–U6, S2/S4. Закончить проверку console clicks, TV depth/zoom, панели Миты/отношений и движения у устройств. Здесь уже много кода, сначала важна комбинированная приёмка.
2. **Игровые сценарии:** G1/G5/G6. QTE/захваты, отдых/сон/выход и смерть/retry — основные потенциальные тупики прохождения. Для смерти адаптер уже добавлен; требуется живой тест.
3. **Предметы и инвентарь:** I1–I3/G7. Телефон, пульт, карточки действий, заметки, приставка/картриджи; затем индивидуальные grips.
4. **Физика/комфорт и мини-игры:** C1–C3/G2–G4. Сидячее управление, руки/стены, бита/моргание, игры ТВ.
5. **Завершение продукта:** S1/S3/S5–S7. Сценопереходы, chat/PTT/context, presence и свежая установка/документация. Это не означает, что все эти пункты требуют нового кода: часть требует только проверки и устранения найденных дефектов.

Рекомендация по порядку — сначала короткая комбинированная проверка направления 1, затем устранение тупиков из направления 2. Пользователь может выбрать другой вектор. Запуск `c8fbe61` разрешён пользователем; новая пачка смерти/вибрации отдельно в игру ещё не устанавливалась.

## Что исключено и что не переносится в host

- Карточная игра исключена по прямому указанию пользователя: базовая реализация не готова.
- Положение смартфона и пульта — отложенный косметический/эргономический этап; исчезновение пульта остаётся отдельной неисследованной проблемой.
- Полноценное управление внешними Win32/WebView/login/file dialogs в шлеме пока не реализовано. Не удалять требования браузера/авторизации ради обхода UI.
- Modding API/release host в этой работе не менялись. Узкие Harmony hooks остаются в моде, не выполняется глобальная подмена Input.GetKey и системная эмуляция клавиш/мыши.
- Подтверждение одного окна не закрывает cleanup/focus/tracking/QTE/scene regression. Нативная установка detour и его исполнение — отдельные проверки, не результат static audit.

## Проверки и критерии закрытия

Текущий static gate: build bootstrap/runtime/XR probe, проверка достижимых interop вызовов/native exports и 22 воспроизводимые проверки политик в `tools/InputPolicyTests` (12 приседания, 10 приоритетов/лимитов вибрации). Они не запускают Unity, player или XR. Ключевые случаи жеста: удержание, повторное взведение, диагональ/поворот, UI → Gameplay, invalid tracking data и reset.

Для закрытия строки очереди нужны: доступный контроллером вход и выход; видимые controls; press/hold/release/cancel без активации нижнего окна; повторный вход; pause, tracking loss/recovery и смена сцены; отсутствие чужих locks/leases/mounts после завершения. Проверять чистый публичный host + установленный мод, фиксировать конкретный build/commit. Шлемовая приёмка предыдущих версий не переносится автоматически на новую DLL.

## Обратная связь из запуска c8fbe61 и следующий фикс

Пользователь: радио нужно крупнее; в открытых интеракциях нужен поворот правым стиком; TV не виден/не управляется; при нажатии мольберта получен краш. В BepInEx LogOutput повторяется native→managed trampoline exception `System.Buffer.Memmove` для `BeginExternalOverride(IntPtr, Vector3, Quaternion, IntPtr, Single, IntPtr, Byte, Il2CppMethodInfo*)`. Это конкретная ошибка перехвата/маршалинга, не доказательство null ссылки в Easel UI и не ошибка запуска SteamVR.

- Полностью снят Harmony hook с BeginExternalOverride: native nullable-аргументы не проходят через этот переходник. После открытия именно мольберта его camera override один раз снимается через безопасный ClearExternalOverride(bool), затем обновляется tracked pose. Штатные Show/Close/brush/drawing не заменяются.
- В собственных Easel/YouTube locks снимается также Look; право поворота использует ту же scoped-проверку, что движение, сохраняя чужие locks/sequence/QTE/death. Перед поворотом из zoom снимается override, а позиция для компенсации берётся уже после восстановления камеры, чтобы не переносить тело к прежней точке zoom.
- Автозакрытие теперь при увеличении горизонтальной дистанции от объекта на **1 м относительно открытия**. Это не абсолютный радиус 1 м: он мог бы закрывать UI сразу после допустимого открытия издалека. Уход вбок без увеличения дистанции не считается удалением.
- Радио: физическая ширина 1.1 → 1.375 м (+25%); mute button 48×48 logical pixels, volume shell 120×36. Исходные размеры восстанавливаются на Release.
- TV: владелец берётся через TVUIController.InteractionController, с parent fallback; ранее один parent lookup мог пропустить sibling-компонент. Панель смещена на 2 см к игроку от центра документа вместо local Z -1 см с недостаточной компенсацией; depth-tested UI не должен оказаться за поверхностью экрана. Добавлен диагностический TV panel bound. Причина фактической невидимости ещё должна подтверждаться новым запуском; статическая правка не закрывает U2.

Регрессионный тест после установки: открыть/закрыть мольберт несколько раз без trampoline errors; радио — размеры/volume/поворот/отход; TV — видимость, controls, zoom/поворот и возврат тела; затем отдельная смерть/retry и реальные haptics. Новый код не считается принятым по результатам старого запуска.
