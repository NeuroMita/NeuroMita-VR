# VR: список адаптации взаимодействий

Аудит исходников 2026-10-17. Разработка и исправления выполняются в отдельном моде. Unity используется как справочник поведения host, не как целевой VR runtime.

Исследованы мод `5705b07` и Unity VR checkout `b89701b7d`; локальная `releases` — `0b4c018ad`. Сравнение с releases по QTE, BatStrikeController, Mita/UI, Cards и World/Interaction выявило в этих каталогах только известное отличие InventoryFullUI. Это не доказывает идентичность всей игры или соответствие каждого файла установленному бинарнику. Наличие компонента в коде также не доказывает его использование в каждой сцене.

Статусы: **сообщено** — наблюдение пользователя; **пробел по коду** — конкретный неподключённый путь; **частично** — адаптер есть, полного покрытия нет; **проверить** — риск, а не установленный дефект. Во время аудита игрок не перезапускался, команды в текущую сессию не отправлялись. Runtime-правки не вносились.

## Дополнительная задача: Discord presence

Пользователь запросил статус `NeuroMita (VR)`. В `Managers/DiscordManager.cs` уже есть `DefaultStateText = "NeuroMita"`, и этот state подаётся в `BuildSnapshot`; итог отправляется через существующий `_client.SetPresence`. Кандидат реализации — узкое изменение state создаваемого snapshot при активной VR-сессии с сохранением details, изображений, party и timestamp. Не заводить второй конкурирующий RPC client. Проверить обратное переключение при StopVr, смене сцены и reconnect Discord. Фактическая доступность точки внедрения в IL2CPP пока не проверена. Формулировка задачи относится к тексту presence; изменение имени самого Discord application — отдельная возможность, здесь не обещается. Приоритет ниже блокеров взаимодействия.

## Как выполнять

1. Сначала убрать тупики управления: панель Миты, QTE/захваты, Back/exit, музыкальный UI. Параллельно сохранить уже подтверждённую работоспособность меню → квартира.
2. Затем полный TV/YouTube и отдых/сон, включая вложенные окна и клавиатуру Toolkit.
3. Затем бита, приставка, мольберт, моргание и смерть. Мольберт и физический удар — отдельные механики, не косметика UI.
4. После доступности функций довести композицию главного меню, HUD и положение предметов. Главному меню можно дать ранний небольшой визуальный фикс, если он не задерживает тупики управления.

Для каждого сценария нужен один владелец ввода и адресованное действие. Предлагаемые QTE bindings должны учитывать занятые A/X/Y/grip/trigger: во время QTE нельзя параллельно отправлять Jump, Chat, Inventory, PTT или world click от того же нажатия. Это требует контекстной маршрутизации, а не просто добавления клавиши в VrInput.

Штатные gameplay-команды, проверки доступности и жизненный цикл остаются в host. Если компонент читает клавиатуру напрямую, мод использует локальный адаптер/узкий IL2CPP hook только этого компонента при активном VR. Глобальная подмена Input.GetKey и эмуляция системной мыши создадут пересечения между QTE, TV, chat и миром. Конкретную доступность IL2CPP методов и пригодность hook нужно проверить в interop установленного публичного релиза до реализации; этот документ не гарантирует готовую точку внедрения.

Универсальная переделка modding API сейчас не входит в работы. Если мод упирается в stripped/private/native путь, сначала фиксировать конкретный блокер и совместимый вариант внутри мода. Не переносить VR-код в releases ради удобства разработки.

## Общая приёмка каждого сценария

- Открытие лучом/действием контроллера, видимость на комфортном расстоянии, доступные подписи контроллера вместо F/Q/E/Mouse.
- Нажать, удержать, отпустить; отпускание за пределами кнопки и отмена не активируют её.
- Закрытие/back, пауза, повторное открытие; не остаётся захвата ввода или невидимого raycast blocker.
- Потеря/возврат tracking, recenter, смена предмета/цели/сцены, уничтожение владельца UI.
- Очистка временных mounts, locks, camera ownership, UI surfaces и подписок; мод не меняет desktop-поведение без активного VR.
- Финальное подтверждение именно на чистом публичном host + BepInEx + мод. Успех на validation host и static audit фиксируется отдельно.

## Статическая пачка 18 октября: бита, моргание, снежки и контекст VR

Этот раздел уточняет исходную очередь. Проверки выполнялись без запуска Unity/игры и без изменения работающей VR-сессии. Нативные hooks новой пачки ещё не проверены в процессе; успешная сборка не означает установку detour или принятую механику в шлеме.

- **Бита:** `VrBatSwing` использует выбранный предмет с действием `BatStrikeAction` и его существующую модель, только в правом item mount. Рабочий конец определяется по длинной оси MeshFilter, без поиска предмета по локализованному имени. Пять интервалов вдоль рабочей половины модели дают шесть swept sphere samples между кадрами. Минимальная скорость 1.5 м/с относительно перемещения тела; взвод после 0.15 с ниже 0.45 м/с, cooldown 0.75 с, одно попадание до повторного взвода. Ближайшее твёрдое препятствие и лучи от головы к руке / от руки к попаданию ограничивают удар через стену. Попадание вызывает штатный `DisableByPlayerStrike`; desktop coroutine, animation mount и invulnerability не запускаются. Кнопочный удар остаётся отдельным штатным вариантом; при активной strike coroutine физический адаптер приостановлен. Пауза, UI, sequence, QTE, смерть, потеря tracking и смена предмета сбрасывают выборку; большой скачок позы/поворота требует повторного взвода. **Открыто:** геометрия конкретной модели, реальные скорости контроллера, крайние углы/быстрые взмахи, частично перекрытый манекен. Кадры с большой дельтой намеренно пропускаются. Это эксперимент, не обещание точной физики биты.
- **Моргание:** узкий hook `PlayerBlinkController.HandleInput`; правая кнопка стика использует существующие `_manualBlinkTriggered` и cooldown при активной механике и разрешённом Gameplay. Нет вызова принудительного моргания, изменения таймера механики или обхода блокировки ввода. Подпись `BlinkHintPresenter` заменяется на RU/EN описание контроллера, клавиша V скрыта. Переключение help этой же кнопкой подавлено, пока механика моргания активна. QTE, pause и sequence блокируют ручной ввод. Сочетание обоих стиков по-прежнему предназначено для recenter. **Открыто:** нативный перехват, показ hint, восстановление help после окончания механики.
- **ТВ «Пингвин / снежки»:** подтверждён конкретный пробел: `LegacyPinguinTelevisionGame.HandleTelevisionInput` пуст, `MT_GameCnowballs.FixedUpdate` и `UpdateGameplay` читают legacy axes. `VrSnowballInput` добавляет левый аналоговый стик в скорость игрока с исходным коэффициентом 8 × fixedDeltaTime и обновляет только его поворот/анимацию/частицы после штатного UpdateGameplay. Адаптер ограничен активной игрой текущего открытого TVGamesModule, паузой, фокусом UI и tracking. Штатные ИИ, правила, раунды, результат и выход остаются в host. Старые key hints этой игры скрываются с сохранением прежнего activeSelf и восстановлением при выходе. **Открыто:** движение и анимация в живом раунде, вход/выход/повтор; legacy keyboard axes продолжают работать параллельно. Для файтинга дополнительный input hook не добавлялся: `LegacyFightTelevisionGame` уже включает external input и передаёт его в `Location4Fight.ApplyExternalInput`.
- **VR-контекст Миты:** postfix `DialogueRuntimeContextBuffer.Capture` создаёт новый batch для текущего персонажа с исходными EntryIds и копией Events плюс одной краткой строкой об использовании шлема/контроллеров и возможных трудностях управления. Общий буфер, runtime_rules и Python не меняются. Исходный workflow передаёт Events в BuildContextSnapshot, даже если EntryIds пуст; Commit продолжает потреблять только исходные записи. Контекст не порождает запрос сам по себе, не накапливается каждый кадр и не остаётся отдельной pending-записью после StopVr. Повтор того же запроса сохраняет его уже захваченный batch по штатной политике retries. При исключении в добавлении контекста сохраняется исходный batch, адаптер перестаёт вмешиваться до переинициализации. **Открыто:** detour и реальный runtime_events в диалоговом запросе; ответ модели не является гарантией конкретной реакции.

### Дополнительная проверка путей отдыха и смерти по исходникам

`PlayerInputController.Tick` передаёт Jump в `Animation.TryRequestStopByUser`; это уже Right A. Выход допускается только в Hold и при allowUserStop, InputLocked и UI state продолжают ограничивать вход. `PlayerSleep.Update` принимает внешний Interact (правый grip), отдельно от A; отказ сна зависит от света, опасности и разрешения Миты. Нужно проверить конкретную кровать/диван/стул: наличие маршрута в исходнике ещё не доказывает работоспособность при их authored locks.

QTE/grab, смерть, сон/выход из отдыха, phone/selfie и оставшиеся редкие предметы сохраняются в очереди приёмки.
